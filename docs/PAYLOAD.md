# Обратная разработка формата пакета терминалов

ChirpStack настроен **без кодека** (Device-profile → CODEC → Payload codec =
*None*). Значит, сеть отдаёт «сырые» байты, а расшифровку дебита / давления /
температуры / накопленного расхода выполняет наш портал (`app/decoder.py`).

Формат пакета производителем документально не задан, поэтому мы
восстанавливаем его по **сопоставленным парам**: одни и те же данные видны
одновременно как сырые байты (в ChirpStack) и как готовые числа (в
существующем портале OPTI Well) для одной скважины в один момент времени.

Как только наберётся несколько таких пар на каждый тип расходомера —
раскладки в `app/decoder.py` заполняются механически, и живая телеметрия
начинает декодироваться.

## Что уже известно

| Тип пакета | Длина | Наблюдения |
|---|---|---|
| flowmeter (без VFD) | 9 байт | пример `0D 20 01 00 07 E5 12 8B 73`, маркер `01 00` на смещении 2 |
| composite (flowmeter + VFD) | 13 байт | байты 0–3 = накопленный расход, маркер `01 00` на смещении 6, «хвост» VFD 5 байт (смещения 8–12) |
| TS | — | метка времени, отдельным сообщением |

### Первый реальный образец (подтверждён из ChirpStack DEVICE DATA)

Скважина **1000**, devEUI `a84041371185a06f`, **FPort 2**, FCnt 8:

```
base64  AAAAAAAAAQAB7nnv/A==
hex     00 00 00 00 00 00 01 00 01 EE 79 EF FC   (13 байт)
        └─────┬────┘ └─┬─┘ └─┬─┘ └─────┬──────┘
        накопл.=0     ?     01 00     VFD-хвост (5 байт)
                            маркер     01 EE 79 EF FC
```

**Выводы:**
- **FPort 2 несёт 13-байтовый composite-пакет** (накопленный расход +
  секция VFD), а не 9-байтовый flowmeter — это та же раскладка, что «wrong
  VFD payload» из журнала. 9-байтовые пакеты = flowmeter без подключённого
  ЧРП.
- Байты **0–3 = накопленный расход** (то самое `flowaccumulated`, которое
  журнал проверяет правилом «> 100000 → TRASH PACKET»). Мгновенный дебит,
  вероятно, **вычисляется как приращение накопленного расхода за интервал**,
  а не передаётся напрямую — иначе в 13 байт не уместить дебит+давление+
  температуру вместе с VFD.
- У скважины 1000 накопленный = `00 00 00 00`: расходомер **офлайн**
  (красный квадрат в «Интервале»). Нулевой образец подтверждает структуру,
  но **не калибрует масштаб** — для этого нужен пакет «живой» скважины.

### Второй реальный образец и побайтовый разбор

Скважина **1566**, FPort 2, FCnt 1: `AAAAAAAAAQAyIOig8g==` =
`00 00 00 00 00 00 01 00 32 20 E8 A0 F2`.

Сравнение 10 VFD-пакетов (2 живых + 8 из журнала) байт за байтом:

| Смещение | Значение | Вывод |
|---|---|---|
| [0] | почти всегда `00` (раз `01`) | флаг статуса |
| [1:6] | `00 00 00 00 00` | **константа** (ноль) во всех пакетах |
| [6] | `01` | **константа** — маркер |
| [7] | `00` (VFD) / `FF` (расходомер отключён) | тип секции |
| [8:12] | 5 байт | высокая энтропия, **у всех «wrong VFD»** |

**Ключевой вывод:** все собранные до сих пор пакеты (включая живые 1000 и
1566) — это VFD-пакеты с **отключённым приводом** (5-байтовый хвост = шум,
поэтому старая система бракует их как «wrong VFD payload»). Байты [0:6] = 0 —
**данных о расходе в этих пакетах нет вообще**.

Реальный расход приходит в **другом типе пакета** — валидном flowmeter-пакете
(форма `0D 20 01 00 07 E5 12 8B 73` из журнала, 9 байт, `byte7 ≠ 00`).
Опрошенные скважины просто шлют VFD-статус с мёртвым приводом.

Типы расходомеров из фонда: `skg`, `skg3v1` → семейство **SKG (СКЖ)**;
`mc2` → **NuFlo MC-II**. FPort 2 = composite; FPort 5 наблюдался только
первым пакетом после подключения (FCnt 0) — вероятно, стартовое/TS-сообщение.

## Почему точечные скриншоты застопорились и что делать

Ручной сбор образцов постоянно попадает на скважины с отключённым приводом
или расходомером (в поле таких большинство — журнал полон «wrong VFD» и
«flowmeter FF»). Чтобы поймать **валидные flowmeter-пакеты живых скважин**,
надёжнее собрать весь поток трафика:

**Рекомендуемый путь — развернуть портал и собрать живой трафик.** Направить
HTTP-интеграцию ChirpStack на `/api/uplink`; каждый пакет сохраняется в
таблицу `raw_uplink` (dev_eui, fport, raw_hex, время). За сутки накопятся
тысячи пакетов, включая валидные flowmeter-пакеты с ненулевым расходом. По
ним раскладка калибруется массово, без ручных скриншотов.

**Быстрый путь — точечно снять зелёную скважину.** Открыть в ChirpStack
именно **810 / 4062 / 4148** (зелёный расходомер, mc2) и снять `data` из 2–3
подряд идущих `up`-событий FPort 2. Если её накопленный расход ненулевой —
хватит на калибровку семейства MC2.

Правило браковки существующей системы уже перенесено: скачок накопленного
расхода > **100000** между пакетами → «TRASH PACKET» (`decoder.py`).

## Что нужно прислать (по 3–5 пар на каждый тип расходомера)

Для каждой пары — одна строка таблицы ниже:

1. **Сырые байты.** ChirpStack → Applications → `KZ865_application` → Devices →
   (скважина) → вкладка **DEVICE DATA** → развернуть событие `up` (стрелка ▾)
   → скопировать поле **`data`** (это base64) и запомнить **`fPort`**.
2. **Известные значения.** В существующем портале OPTI Well для **той же
   скважины** в тот же момент — снять: дебит `Qж`, накопленный расход,
   давление `Pлин`, температуру `Tлин` (что показывается).
3. **Тип расходомера** — из фонда (`skg` / `skg3v1` / `mc2`).

### Таблица для заполнения

| Скважина | Тип расх. | FPort | data (base64 или hex) | Дебит | Накопл. | Pлин | Tлин |
|---|---|---|---|---|---|---|---|
| 1000 | ? | 2 | `AAAAAAAAAQAB7nnv/A==` | 0 (VFD откл.) | 0 | — | — |
| 1566 | ? | 2 | `AAAAAAAAAQAyIOig8g==` | 0 (VFD откл.) | 0 | — | — |
| **810 / 4062 / 4148** | mc2 | 2 | `…` (нужен зелёный) | | | | |
| _(любая)_ | ? | 5 | `…` | | | | |

Чем больше разброс значений между образцами (разный дебит, разное давление),
тем точнее вычисляются смещения и масштаб.

## Как я превращаю пары в декодер

```bash
# Разложить пакет на все возможные интерпретации:
python tools/analyze_payload.py "DSABAAflEotz"          # base64 или hex

# Найти, где в пакете лежит известное значение (напр. дебит 12.5):
python tools/analyze_payload.py "DSABAAflEotz" --find 12.5

# Сравнить пакеты одного типа: какие байты постоянные, какие меняются:
python tools/analyze_payload.py --diff "<data1>" "<data2>" "<data3>"
```

`--find` перебирает float32/uint16/uint32/int16 (LE и BE) на всех смещениях
и типовые масштабы (×0.1, ×0.01, ×10 …) и печатает, где именно получается
искомое число. Найденные `offset` / `fmt` / `scale` вписываются в таблицы
`FLOWMETER_LAYOUTS` / `VFD_LAYOUT` в `app/decoder.py`, поле помечается
`confirmed=True` — и декодирование включается.

## Пока идёт калибровка

Каждый принятый uplink сохраняется целиком в таблицу `raw_uplink`
(`dev_eui`, `fport`, `raw_hex`, время) — **ничего не теряется**. Когда
раскладка подтверждена, накопленные сырые пакеты можно расшифровать задним
числом. До этого портал полностью работает на данных фонда (2420 скважин из
CSV): дашборд, фонд, карта, отчёты, радиоанализ.
